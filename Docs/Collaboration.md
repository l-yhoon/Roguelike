# 협업 규칙

## 작업 영역

사람 이름으로 폴더를 만들지 않고 기능별로 파일을 모읍니다. 아래는 코딩 영역 구분이며, 최종 담당자는 팀에서 정합니다. 회의에서 확정한 역할은 README에 유지했습니다.

| 영역 | 코드 폴더 | 책임 | 첫 결과물 |
| --- | --- | --- | --- |
| 전투 | `Scripts/Combat` | 턴, 체력, 방어도, 에너지, 적 의도·행동, 피해 계산, 승패 | 카드 입력을 받아 한 턴 진행 |
| 카드 | `Scripts/Cards` | 카드 정의, 시작 덱, 드로우, 손패, 버림패, 소멸 | 카드를 뽑고 사용 후 옮기기 |
| UI | `Scripts/UI` | 손패 배치, 카드 선택·대상 선택, 상태·의도 표시, 버튼 | 임시 이미지로 전투 화면 구성 |
| 진행 | `Scripts/Progression` | 맵 노드·경로, 전투 진입, 보상, 휴식, 유물 획득, 진행 상태 | 노드 → 전투 → 보상 → 맵 |

`Scripts/Core`는 여러 기능에서 함께 쓰는 최소 공통 타입과 화면 전환에 사용합니다. 공통 타입 변경은 영향을 받는 담당자와 먼저 맞춥니다. 모든 코드를 Core나 하나의 GameManager에 모으지 않습니다.

## 기능 연결 전에 정할 규칙

다음은 구현 시 사용할 책임 기준입니다. 아직 코드나 API가 만들어진 것은 아닙니다.

- 카드 정의에는 고정 ID, 이름, 비용, 설명, 대상 종류, 효과, 이미지를 둡니다. 설정 에셋은 `Data/Cards`에, 정의 클래스는 `Scripts/Cards`에 둡니다.
- 카드 담당은 전투 중 덱·손패·버림패·소멸 상태를 관리합니다. 진행 담당은 보상으로 추가된 카드를 포함한 이번 플레이의 보유 덱을 관리하고 전투 시작 시 전달합니다.
- UI는 카드 사용을 요청합니다. 전투 담당이 현재 턴·대상·에너지를 확인하고 효과를 적용합니다. 사용 성공 후에만 카드 담당이 손패에서 해당 카드를 옮깁니다.
- 체력·에너지·방어도·피해 수치 변경은 전투 담당 코드에서 처리합니다. UI는 상태를 표시하고 입력을 전달합니다.
- 카드·적·유물 ScriptableObject는 원본 설정입니다. 현재 체력, 강화 효과 같은 실행 중 상태는 별도로 보관합니다.
- 전투 종료 결과를 진행 담당에게 전달합니다. 진행 담당이 보상을 적용하고 맵으로 복귀시킵니다.
- 첫 유물은 획득 시점이나 전투 시작처럼 적용 시점이 단순한 효과부터 만듭니다. 전투 중 효과는 전투 담당과 연결 방식을 먼저 정합니다.

첫 작업 전에 타입 이름과 주고받을 값을 담당자끼리 정하고 이 문서에 기록합니다.

## 씬과 Prefab

- 새 씬은 `_Game/Scenes`에 만듭니다. 향후 이름은 `MainMenu`, `Map`, `Battle`처럼 역할이 드러나게 정합니다. 현재는 SampleScene만 존재합니다.
- 씬마다 조립 담당 한 명을 정합니다. 나머지는 카드, 적, 상태창 등을 Prefab으로 만들어 전달합니다.
- 손패 표현과 카드 선택 코드는 UI, 카드 목록과 드로우 규칙은 Cards에 둡니다.
- 이미지와 Prefab도 여러 사람이 같은 파일을 수정하면 충돌할 수 있습니다. 작업 중인 파일을 팀에 공유합니다.
- 파일 이동·이름 변경은 Unity Project 창에서 합니다. 에셋과 `.meta`는 항상 함께 커밋합니다.
- 빈 작업 폴더를 Git에 유지하기 위해 `.gitkeep`을 넣었습니다. Unity가 생성하는 `.meta`도 함께 관리합니다.

## 화면·리소스 기준

첫 UI 작업 전에 기준 해상도, Canvas 스케일 방식, 폰트와 기본 카드 크기를 합의합니다. 임시 이미지로 흐름을 먼저 연결합니다. AI 리소스는 카드·캐릭터·배경의 스타일을 맞추고, 원본 위치와 생성 도구·사용 조건을 필요에 따라 기록합니다.

## Git 작업 순서

1. 진행 중인 변경을 커밋하고 main으로 이동합니다.
2. `git pull --ff-only origin main`으로 최신 변경을 받습니다.
3. `git switch -c feature/기능명`으로 브랜치를 만듭니다. 예: `feature/card-draw`, `feature/map-nodes`.
4. 한 기능 단위로 커밋하고 해당 브랜치를 push합니다.
5. PR에 변경 내용, Unity에서 실행한 씬과 확인 결과, 연결에 필요한 작업을 적습니다.
6. 다른 팀원 한 명이 확인한 후 main에 합칩니다. main은 열고 실행할 수 있는 상태를 유지합니다.

Unity 버전 변경, 패키지 추가, ProjectSettings 변경은 팀에 먼저 공유합니다. 새로 clone한 팀원은 README의 Unity 버전과 실행 씬을 기준으로 프로젝트를 엽니다.

## 첫 공동 확인

- 네 명 모두 Unity Hub에서 `SlaytheSpire`를 열 수 있는지 확인합니다.
- SampleScene이 열리고 Console에 오류가 없는지 확인합니다.
- 네 개 작업 영역의 담당자와 첫 씬 조립 담당자를 확정합니다.
- 카드 사용 요청과 전투 종료 결과를 어떻게 전달할지 합의합니다.
- 맵 → 전투 → 보상 → 맵 흐름부터 연결합니다.
